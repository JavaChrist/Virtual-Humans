Vue d'ensemble & concepts clés

◫Deux briques séparées

SDK (characters/) = l'identité complète d'un personnage virtuel (fiches, mémoire, assets).
Studio (studio/) = l'appli Next.js qui lit le SDK et génère les médias. On ne mélange jamais les deux.

☺Personnage actif

Sélecteur global en haut du menu. Toutes les pages (image, voix, vidéo…) travaillent sur ce personnage. Le choix est mémorisé dans le navigateur.

#characterId vs characterCode

characterId = identifiant technique (URL/API, ex. tom). characterCode = code métier lisible (ex. TOM-001). Les deux sont uniques : deux packages ne peuvent pas les partager.

🔒Identité verrouillée

Pour garder le même visage d'un plan à l'autre : une image de départ (photo du perso ou décor généré) sert de 1re frame ; la vidéo se contente de l'animer. Pas d'invention de visage.

Le flux type : on choisit le personnage → on prépare une image (tenue/décor) → on anime en vidéo (muette) → on ajoute la voix par lip-sync → on assemble les plans en une pub de 60 s. Chaque génération est estimée en $ avant l'appel.

Les modules de l'interface (menu de gauche)

◧Tableau de bord
/ (page.tsx)

Vue d'accueil du personnage actif : cartes Identité, Apparence, Personnalité, Voix. Indicatif — le pilotage se fait dans les Studios.

☺Personnages
/characters · /characters/[id]

Liste des packages détectés + santé de chacun. La fiche détaille tenues, identité, poses, expressions, voix, capacités, limites, 11 mémoires, jauges de personnalité, phrases candidates et alertes qualité (assets manquants, collisions).

◈Studio Scène
/scene

Compose une présentation : tenue + lieu + pitch + produit. Bloc Décor (PuLID Flux) place le perso dans un lieu, puis Kling l'anime (identité verrouillée). Compteur de temps pendant la génération.

▦Produits / Apps
/products

Bibliothèque des apps à promouvoir : nom, pitch, couleur, URL et captures d'écran (ajout/suppression). Réutilisées dans Studio Scène.

▣Studio Image
/image

Génère des images via OpenAI (gpt-image-1) : taille, qualité, quantité. Sert de bibliothèque de références par personnage.

◉Studio Voix
/voice

Synthèse vocale ElevenLabs. Chaque personnage a sa propre voix (voice/config.json : Mei et Tom ont des voiceId distincts).

►Studio Vidéo
/video

Génération vidéo unitaire. Choix du modèle (Veo, Seedance, Kling, Runway, MiniMax), durée et ratio adaptés au modèle. File d'attente + suivi de statut.

◑Studio Lip-sync
/lipsync

Synchronise une voix sur une vidéo muette (VEED ou Sync v3). C'est l'étape qui fait « parler » le personnage face caméra.

▤Storyboard 60 s
/storyboard

Enchaîne 7 plans (preset micro-trottoir). Kling image→vidéo pour l'identité, Décor par plan (un lieu différent, visage conservé), puis assemblage FFmpeg en une vidéo de ~60 s.

$Budget
/budget

Détail des dépenses estimées (par type/modèle) + total. Bouton reset (aussi présent sur la carte du menu) pour repartir de zéro par campagne.

⚙Réglages
/settings

État des clés API (OpenAI, ElevenLabs, fal.ai), modèle de .env.local, source du SDK et tarifs voix.

✔Modales de confirmation
components/confirm.tsx

Remplace les pop-ups du navigateur. Hook useConfirm() → modale stylée (Échap = annuler, Entrée = valider), variante rouge pour les suppressions.

Le runtime « personnage » (le cerveau du SDK)

Dossier studio/src/runtime/character/ — lit un package sur disque, le valide strictement, et l'expose via une API versionnée. Aucun repli silencieux : en cas de problème, une erreur typée explicite.

loader.ts

Charge un package depuis le disque, valide, remonte les problèmes non bloquants (assets manquants…) et invalide les assets marqués.

schema.ts (Zod)

Schémas stricts : identité, tenues, voix, personnalité, mémoires, qualité des données. Type-safe, échec explicite si malformé.

registry.ts

Recense tous les personnages et applique la garde d'unicité : collision de characterId/characterCode → erreur (HTTP 409), pas de choix arbitraire.

personality.ts

Extrait la personnalité du Markdown (02_PERSONALITY.md) : traits, jauges, style, phrases candidates.

errors.ts

Hiérarchie d'erreurs : NotFound, PackageInvalid, DocumentMissing, IdentityAssetMissing, DuplicateId/Code…

http.ts + api/v1/characters

Mapping pur lookup → statut/corps HTTP. Routes /api/v1/characters et /api/v1/characters/[id] (testables, 200/404/409).

Recette : produire une pub micro-trottoir de 60 s

  1. Choisir le personnage actif (Mei ou Tom) dans le menu de gauche.
  2. Préparer le produit dans « Produits / Apps » : nom, pitch, captures d'écran de l'app.
  3. Ouvrir Storyboard 60 s : les 7 plans du preset micro-trottoir sont pré-remplis.
  4. Frame de départ : sélectionner une photo d'identité (verrouille visage + tenue).
  5. Décor par plan (optionnel) : saisir un lieu (« rue animée »…) puis « Générer le décor » → le perso est placé dans le décor, identité préservée.
  6. Générer les plans (Kling image→vidéo, muet) — ~3–4 min pour 5 s, c'est normal.
  7. Voix + lip-sync : passer chaque plan (ou le montage) dans Studio Lip-sync pour faire parler le personnage.
  8. Assembler les plans en une vidéo de ~60 s (FFmpeg merge).
  9. Surveiller le budget : chaque étape s'ajoute au cumul ; reset en début de campagne.
