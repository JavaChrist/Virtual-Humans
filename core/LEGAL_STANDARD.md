# LEGAL STANDARD

> Virtual Humans SDK
> Standard global juridique, éthique et de conformité des personnages virtuels
> Version : 1.0.0
> Statut : actif

---

# 1. Objectif

Ce document définit les règles juridiques, éthiques et de gouvernance applicables à tous les personnages du **Virtual Humans SDK**.

Il constitue le référentiel commun permettant de garantir que chaque Virtual Human est créé, utilisé, diffusé et exploité dans le respect :

* des lois applicables ;
* des droits des personnes ;
* des droits de propriété intellectuelle ;
* des licences des fournisseurs ;
* des réglementations sur l'IA ;
* des règles internes du SDK.

Ce standard s'applique à tous les personnages présents et futurs.

---

# 2. Champ d'application

Ce standard couvre notamment :

* les images ;
* les vidéos ;
* les voix ;
* les textes ;
* les animations ;
* les conversations ;
* les réseaux sociaux ;
* les présentations commerciales ;
* les applications ;
* les sites web ;
* les contenus marketing ;
* les contenus générés par IA.

---

# 3. Principe fondamental

Un Virtual Human est une création numérique.

Il ne doit jamais créer une confusion volontaire avec une personne réelle.

Chaque personnage possède une identité propre, documentée et versionnée.

---

# 4. Source de vérité juridique

Les références officielles sont, par ordre de priorité :

```text
99_CHARACTER_LOCK.md
CHARACTER_STANDARD.md
LEGAL_STANDARD.md
Documentation officielle du personnage
Contrats
Licences
```

Les contenus générés automatiquement ne modifient jamais les règles juridiques.

---

# 5. Droits d'auteur

Tous les contenus créés dans le SDK doivent disposer d'un statut clair.

Chaque asset doit être identifiable comme :

* création originale ;
* contenu sous licence ;
* contenu libre de droits ;
* contenu sous contrat ;
* contenu interne.

Les droits doivent pouvoir être démontrés à tout moment.

---

# 6. Images de référence

Les images utilisées comme références doivent être autorisées.

Il est interdit d'utiliser volontairement :

* une célébrité ;
* un mannequin identifiable ;
* une personne privée ;
* une photographie protégée sans autorisation.

Les personnages doivent disposer de leurs propres références officielles.

---

# 7. Voix

Les voix utilisées doivent respecter les licences des fournisseurs.

Il est interdit :

* d'usurper la voix d'une personne réelle ;
* d'imiter une célébrité sans autorisation ;
* de générer volontairement une confusion.

La voix officielle d'un personnage appartient au SDK et non au fournisseur technique.

---

# 8. Marques

Les marques citées dans les contenus doivent être utilisées conformément au droit applicable.

Toute utilisation commerciale doit respecter :

* les droits des titulaires ;
* les contrats éventuels ;
* les chartes graphiques lorsque cela est nécessaire.

---

# 9. Produits

Les produits présentés doivent être représentés fidèlement.

Il est interdit :

* d'inventer des caractéristiques ;
* de créer de faux avis ;
* de falsifier des démonstrations ;
* de présenter des fonctionnalités inexistantes.

---

# 10. Transparence

Lorsqu'un contexte l'exige, il doit être clairement indiqué que le contenu est produit ou assisté par une intelligence artificielle.

La transparence est privilégiée lorsque l'utilisateur pourrait raisonnablement croire qu'il interagit avec une personne réelle.

---

# 11. Protection des données

Le SDK ne doit pas intégrer de données personnelles sans base légale.

Les mémoires des personnages ne doivent pas contenir :

* des informations personnelles non autorisées ;
* des données sensibles ;
* des informations confidentielles ;
* des secrets commerciaux non autorisés.

---

# 12. Respect des personnes

Les personnages ne doivent pas être utilisés pour :

* diffamer ;
* harceler ;
* discriminer ;
* manipuler frauduleusement ;
* usurper une identité ;
* porter atteinte à la réputation d'une personne.

---

# 13. Contenus interdits

Le SDK interdit notamment la création de contenus destinés à :

* la fraude ;
* l'usurpation d'identité ;
* la désinformation volontaire ;
* le chantage ;
* les faux documents ;
* les deepfakes trompeurs ;
* les contenus haineux ;
* les contenus illicites.

---

# 14. Deepfakes

Les technologies de génération d'image ou de vidéo ne doivent jamais être utilisées pour reproduire une personne réelle sans autorisation.

Les personnages du SDK doivent rester des identités originales.

---

# 15. Responsabilités

L'intelligence artificielle propose.

Le propriétaire du SDK valide.

Toute publication officielle nécessite une validation humaine.

---

# 16. Compatibilité réglementaire

Le SDK doit pouvoir évoluer afin de rester compatible avec les réglementations applicables, notamment celles relatives à l'intelligence artificielle, à la propriété intellectuelle, à la protection des données et à la consommation.

---

# 17. Archivage

Les contenus officiels doivent rester traçables.

Chaque publication importante doit pouvoir être reliée :

* à une version du personnage ;
* à une version des assets ;
* à une version des prompts ;
* à une version des workflows.

---

# 18. Audit

Le SDK doit permettre un audit complet de :

* l'origine des assets ;
* la chaîne de génération ;
* les validations ;
* les modifications ;
* les versions.

---

# 19. Évolution

Toute évolution juridique ou réglementaire doit conduire à une mise à jour de ce standard.

Les changements doivent être documentés et versionnés.

---

# 20. Règle finale

La conformité juridique prime toujours sur la qualité technique, la rapidité de production ou le réalisme d'une génération.

Aucun contenu ne doit être publié si son statut juridique, ses droits d'utilisation ou sa conformité ne peuvent être établis avec un niveau de confiance suffisant.
